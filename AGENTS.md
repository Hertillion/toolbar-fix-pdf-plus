# Repository Guidelines

## Project Structure & Module Organization

This repository is an Obsidian plugin written in TypeScript. `src/main.ts` is the plugin entry point. Core plugin behavior lives under `src/lib/`, UI dialogs under `src/modals/`, Obsidian/PDF.js monkey patches under `src/patchers/`, Markdown post-processing under `src/post-process/`, shared helpers under `src/utils/`, and Vim-like PDF navigation under `src/vim/`. Global plugin CSS is in `styles.css`. The bundled output `main.js` is generated by esbuild and ignored by ESLint; do not edit it by hand.

## Build, Test, and Development Commands

- `pnpm install`: install dependencies from `pnpm-lock.yaml`.
- `pnpm dev`: run esbuild in watch mode with inline sourcemaps for local Obsidian testing.
- `pnpm build`: run TypeScript checking, then create a minified production `main.js`.
- `pnpm lint`: run ESLint over `src/**/*.ts` and `src/**/*.tsx`.
- `pnpm lint:fix`: apply safe ESLint fixes.
- `pnpm version`: run `version-bump.mjs`, update `manifest.json` and `versions.json`, and stage those files.

## Coding Style & Naming Conventions

Follow `.editorconfig`: UTF-8, LF line endings, final newline, tabs for indentation, and tab width 4. ESLint uses recommended TypeScript rules, requires semicolons, and treats unused variables as errors while allowing unused function arguments. Match existing naming: kebab-case filenames such as `pdf-backlink.ts`, PascalCase classes and types, and camelCase functions, variables, settings keys, and methods.

## Testing Guidelines

No dedicated automated test framework is currently configured. Before opening a PR, run `pnpm build` and `pnpm lint`. Manually validate behavior in an Obsidian vault, especially changes touching PDF viewers, backlinks, annotations, Vim mode, settings, patchers, or CSS. For bug fixes, reproduce the issue first when possible and include the validation steps in the PR.

## Commit & Pull Request Guidelines

Use short, direct commit messages consistent with history, for example `Fix #476`, `update deps`, or `release: 0.40.31`. Create an issue before submitting a pull request so the change can be discussed. Read `.github/CONTRIBUTING.md`, keep the PR template acknowledgement checked, and include a concise description of the change. Add screenshots, recordings, reproduction notes, or affected Obsidian/PDF++ settings when UI or PDF behavior changes.
